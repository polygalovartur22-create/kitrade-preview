# KITRADE — полный handoff сайта

Архив содержит полную рабочую копию сайта: HTML, исходные и собранные CSS-файлы, JavaScript, изображения, данные каталога, служебные файлы Netlify и историю Git.

## Как открыть сайт локально

Для корректной работы не открывайте `index.html` двойным кликом через `file://`. Запустите локальный HTTP-сервер из корня проекта.

### Вариант 1 — готовый скрипт

Требуется Python 3:

```powershell
python .\serve-local.py
```

После запуска откройте:

```text
http://127.0.0.1:4173/index.html
```

Остановка сервера: `Ctrl+C`.

### Вариант 2 — любой статический сервер

Можно использовать VS Code Live Server, `python -m http.server`, Netlify CLI или другой статический HTTP-сервер. Корнем публикации должна быть текущая папка.

## Основные файлы

- `index.html` — главная страница.
- `catalog.html` — отдельная страница каталога.
- `tilda-autoscale.css` — финальный слой адаптивных правок.
- `artboard-compiled.css` — собранный CSS, который подключён в `index.html`.
- `build-artboard-css.mjs` — пересборка `artboard-compiled.css`.
- `script.js`, `home-catalog.js`, `catalog-app.js` — основная логика интерфейса и каталога.
- `kitrade-parts-data.js` — данные каталога.
- `assets/` — изображения и другие медиафайлы.
- `assets/external-media/` — локальная копия всей бывшей медиатеки Cloudinary: фотографии, обложки и видео.
- `assets/external-media/manifest.json` — соответствие исходных CDN-ссылок локальным файлам.
- `netlify.toml`, `_headers`, `_redirects`, `404.html` — конфигурация публикации.

## Как пересобрать CSS

После изменения исходных CSS-файлов выполните:

```powershell
node .\build-artboard-css.mjs
```

Скрипт заново создаст `artboard-compiled.css`. Если браузер показывает старую версию, измените параметр версии у подключения `artboard-compiled.css` в `index.html` и обновите страницу без кеша.

## Текущее состояние

На момент упаковки `index.html` подключает `artboard-compiled.css?v=91`. Архив создан из фактической рабочей копии со всеми текущими изменениями, включая незакоммиченные файлы.

Медиафайлы Cloudinary сохранены локально, поэтому фотографии заказов, обложки и видео не зависят от доступности исходного CDN. Внешними остаются только настоящие сервисные ссылки и встраивания: карты, ВКонтакте, Rutube и Яндекс Метрика.

## Постоянные URL каталога

Каталог собирается в статические страницы для размещения на REG.RU/VPS с nginx. Товарный адрес не зависит от марки, модели или категории:

```text
/catalog/product/fara-pravaya-geely-monjaro-original-1170/
```

Число в конце — внутренний постоянный ID. Оно не является ID Avito и не меняется при обновлении названия, цены, категории или совместимости. Карточки содержат обычные HTML-ссылки. Обычный клик открывает быстрый просмотр без изменения URL; новая вкладка и отключённый JavaScript открывают полноценную страницу товара.

Основные служебные файлы:

- `catalog-url-map.json` — постоянный реестр ID и URL; этот файл нельзя удалять или создавать заново при очередной выгрузке.
- `public/catalog-urls.json` — полный экспорт адресов для Директа и последующих SEO-работ.
- `catalog-url-data.js` — компактная карта URL для интерфейса сайта.
- `deploy/nginx-catalog-routes.conf` — правила nginx для 301, статических маршрутов и настоящего ответа 404.
- `dist/` — полностью готовая к загрузке сборка сайта.

После замены или обновления `kitrade-parts-data.js`:

```powershell
npm run catalog:sync
npm run verify
```

Первая команда сознательно изменяет постоянный реестр и добавляет ID только новым товарам. Исчезнувшая из очередной выгрузки позиция не удаляется: она получает статус `unlisted`, а её URL и сохранённая карточка остаются в сборке. Вторая команда запускает тесты, пересобирает `dist/` и проверяет все товарные страницы и canonical.

Если в источнике переименовали марку или модель, сначала добавьте новое написание в `source_names` соответствующей сущности в `catalog-url-map.json`. Тогда старый slug сохранится и не появится новая сущность из-за одного переименования.

Для публикации загружается содержимое `dist/`, после чего правила из `deploy/nginx-catalog-routes.conf` объединяются с действующим `server`-блоком nginx. В этой подготовительной версии публикация на сервер не выполнялась.
